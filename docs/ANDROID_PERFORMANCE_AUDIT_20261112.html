PERF-01 · P1 · Image Pipeline · Source + trace

Reuse remote cover requests across cards, stacks and details

Implemented: scoped memory cache and shared flights. Implementation evidence.

Before · audit baseline

Each remote cover composition calls the repository, performs link/entity lookups, then executes and decodes another authenticated image request. Local thumbnails have a separate 200-entry cache; remote bitmaps are held only by composed producers. Re-entering a discarded item can refetch/redecode.

produceState(null, item.id, item.imageTag) {
  value = repository.loadJellyfinCoverBitmap(item.id, item.imageTag)
}

After · implemented backend

LibraryRepository now owns CoverBitmapCache. Remote and retained-remote artwork reuse a byte-budgeted process-local LRU (heap/16, capped32MiB) keyed by URL/server/user/session/item/tag/width. Same-key concurrent callers share a flight; one cancelled card preserves other readers, the final reader cancels unfinished work. Failures/nulls stay retryable. Session/content invalidation clears memory and rejects late results. No disk or HTTP cache was added.

jellyfinCoverCache.get(scopedKey) {
    // retained local art first, then existing authenticated client
    // reject changed session before publication
}

Evidence: JellyfinClient.kt:421–449; LibraryRepository.kt:1001–1015; LibraryScreen.kt:1993,2441,2593. Scroll trace: 27 background decodeBitmap slices, 123.86 ms inclusive total, max 8.44 ms; these are decode events, not a measured request count or proof that all were avoidable.

Verification and remaining measurement: Focused tests verify byte eviction, scope/tag/width isolation, cancellation, failed retry and late-result rejection. New repository integration checks eight concurrent callers plus re-entry make one image request; reconnect forces a fresh request. Final shell-568 shared/unit/build/lint gate passed:143 shared passes; each Android flavor186 total/185 passed/1 skipped, zero failures. Evidence is linked below. Current-candidate frame and memory snapshots are recorded separately; no isolated before/after gain is claimed.

UI coordination: Existing suspending loader API and image-recovery keys are retained. Main-grid target-size requests and bounded remote/retained-remote decodes are now implemented; creator/legacy/detail callers retain400px defaults. The separate200-entry local-only thumbnail cache remains future work.

PERF-03 · P1 · Storage & DB · Source

Stop validating every retained archive after progress-only changes

Implemented: shared fingerprint validation. Implementation evidence.

Before · audit baseline

LibraryViewModel.readableComics, catalogue downloads, and downloaded-copy observation independently open archives and read page zero. They are off Main, which is good, but Room progress emissions can invalidate the entire collection and repeat expensive ZIP/RAR work and per-link DB reads.

repository.comics.map { rows ->
  rows.filter { openArchive(it.filePath).use { a -> a.readPage(0).isNotEmpty() } }
}

After · implemented backend

ComicFileAvailability serializes and shares successful browse-time validation across repository observers and ViewModels. It stats path/size/high-resolution modification/creation/file identity/page count on IO and caches one success per active comic ID; the shared row stream prunes removed IDs. Progress-only rows reuse validation. Import/delete/restore invalidates cached state. getReadableJellyfinComic always forces full archive validation before remote-copy Read.

val readableComics by lazy {
  comics.mapLatest { rows ->
    availability.retain(rows.map { it.id }.toSet())
    rows.filter { availability.isReadable(it) }
  }.stateIn(observationScope, WhileSubscribed(5000), emptyList())
}
// Read: availability.isReadable(comic, force = true)

Evidence: LibraryViewModel.kt:106–118; JellyfinCatalogueViewModel.kt:77–87; LibraryRepository.kt:981–998,1019–1044. This is a source-verified work-amplification risk; no large retained-library CPU/IO benchmark was captured.

Verification and remaining measurement: Eight concurrent validation callers plus a progress-only update perform one validation in the deterministic fixture; forced Read performs another. Tests cover changed/deleted/replaced files, explicit invalidation, failed-validation retry and corruption after warming. Metadata fingerprints are not proof of content integrity. Large retained-library IO/latency is still unmeasured.

UI coordination: readableComics/downloadedCopies APIs remain. Observation scope is separate from finite sync work. No file format, schema, progress journal or retention policy changed.

PERF-05 · P2 · Network & Serialization · Source

Bound metadata-refresh amplification before changing HTTP or serializers

Before · audit baseline

Every refresh resolves distinct parent folders serially; each verified folder uses detail + ancestry requests. Each completed page serializes the growing full inventory into one Room JSON row. Repeated full-snapshot writes grow cumulatively with page count. ResponseBody.string + JSONObject retains a per-page string/tree, but network page sizes are already bounded.

saveIndex(snapshotOfAllSeenEntries)

Reuse verified ancestry within a current scoped refresh; evaluate bounded concurrent folder validation. Move index map work to Default. Only normalize metadata rows/use transaction-batched upserts when 10k-scale measurements justify it; retain complete-pass-only removals.

PERF-06 · P2 · Memory & GC · Source + sample

Budget caches in bytes and verify actual decoded dimensions

Partial implementation: CoverImageDecoder now bounds remote/retained-remote thumbnails and the main grid requests size buckets. Local-only thumbnail cache, imported cover generation and PageLoader sampling remain unchanged. Reader image-quality policy is outside this patch.

Before · audit baseline

The local cover cache holds 200 entries regardless of bitmap size; imported cover downsampling targets a minimum-ish sample, so a 1000px long edge is stored at 1000px despite COVER_MAX_DIMENSION=600. PageLoader's similar sampling can decode a 4000px scan at 4000px for its 2560px target. Page cache is byte-bounded and archive reads are serialized already.

LruCache<String, ImageBitmap>(200)
while (longEdge / (sample * 2) >= target) sample *= 2

After · proposed, not implemented

Use byte-sized thumbnail caching and target-size decode requests, including a guard if the server ignores maxWidth. Define image quality limits separately for reader zoom versus thumbnails; verify both-platform policy before changing PageConstants. Audit close/retry job ownership without removing final durable progress saves.

// Proposed: byte-budgeted cache, sizeOf = allocationByteCount.
// Choose sample/scale from required display quality and measured heap.
// Do not claim 'target' is a hard bound when power-of-two sampling isn't.
